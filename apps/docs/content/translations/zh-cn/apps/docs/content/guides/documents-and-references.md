# 文档与引用

逻辑文档是一组共享链接定义、脚注定义和编号的内容。Markdown 语法单元是一次交给一个渲染器解析的完整字符串；这两种边界不必相同。

## 什么时候需要协调

普通消息使用一个渲染器最直接。只有同一文档因为布局、独立更新或虚拟列表而分成多个渲染器时，才在外层使用该框架的 `AIMarkdownDocuments`，并给各部分相同的显式 `documentId`。

协调共享引用定义、脚注编号和汇总脚注区，不会把两个组件里的半段围栏、公式或表格拼成完整语法。不同消息使用不同文档身份，避免交叉引用。

## 顺序、挂载与定义变化

React 的引用顺序默认跟随注册顺序；乱序挂载或虚拟化重挂载时使用稳定的 `documentIndex`。不要用重挂载顺序冒充文档顺序。平滑呈现的排队是另一套生命周期规则，不能用引用顺序推断播放顺序。

注册与贡献属于宿主的提交/挂载阶段，卸载必须释放。晚到定义会更新已挂载的引用。服务端只使用当前片段可见的本地定义，不能假定所有跨片段引用已解析；水合后才读取已提交的共享贡献。

## 框架差异

React 的协调依赖 `blockMemo` 路径，关闭它会留下字面引用。文档容器的孤立引用策略优先于子渲染器。Vue 没有 `blockMemo`，孤立引用策略由各渲染器单独决定。

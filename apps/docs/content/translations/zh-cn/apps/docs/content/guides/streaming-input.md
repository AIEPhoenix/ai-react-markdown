# 流式输入

`content` 始终是当前完整的 Markdown 字符串，不是刚收到的增量片段。组件不负责请求模型接口；应用负责网络传输、解码、消息协议、错误处理和重试。

## 区分几个状态

| 概念       | 含义                                             |
| ---------- | ------------------------------------------------ |
| 传输片段   | 网络层一次收到的数据，不一定是完整字符或完整事件 |
| 累积源文本 | 把解码并解析后的文本依次追加得到的字符串         |
| 可见前缀   | 平滑呈现时已经显示的部分                         |
| 生产端完成 | 网络逻辑已确认本次生成结束                       |
| 呈现完成   | 已收到的内容全部显示完毕                         |

先用流式解码器处理 UTF-8，再按照 SSE 或其他传输协议解析事件，最后追加事件中的文本。不能把每次 `read()` 都当作一条完整事件，也不要丢弃末尾尚未闭合的数据。

## 普通消息与文档边界

一条聊天消息通常对应一个渲染器。不要在每个 token 到达时增加一个组件，否则公式、列表、围栏和引用可能被拆断。真正按布局拆分的逻辑文档见[文档与引用](documents-and-references.md)。

## 平滑呈现、完成与取消

平滑控制器按字素簇显示新增内容，避免拆开组合字符。输入的 `streaming` 描述生产端，输出的 streaming 状态会在生产端结束后继续保持，直到积压文本排空。

`flush()` 用于跳过可用内容的动画；生产端仍活跃时，最后一个未确认的字素可能继续保留。它不取消请求。用户取消时应同时中止传输，并按产品策略保留或清除已经收到的文本。

内容替换通常直接显示新文本，不把旧消息的剩余动画带入新消息。新消息应使用新的稳定组件身份。具体行为见 [React 平滑输出](smooth-streaming.md)和 [Vue 流式渲染](vue-streaming.md)。
